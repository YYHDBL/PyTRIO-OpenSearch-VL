# Base、SFT、RL：两阶段训练带来了什么

在这99道相同题上，SFT将正常结束作答从82题提高到97题，并把主模型输出从约431K tokens降到98K；准确率从53题变成50题。RL后格式合规度和验证集组合奖励提高，但同题benchmark准确率为49题，工具调用和输出token数与SFT近似。两阶段训练改善了Agent执行流程，当前实验未显示准确率收益。

主模型均为Qwen3.5-4B。SFT使用2048条轨迹、LoRA rank32、1轮、512次更新；标准化题面去重为1592个题面，2048个问图组合都不同。RL从最终SFT State开始，计划100题、其中93题完整参与更新，每题4条在线轨迹，共372条有效rollout、25次更新；多轮rollout拆成1598个训练Datum。[统计依据](evidence/training-stage-comparison-v1.json)由真实记录重新计算，题目、参考答案和评分对应回答哈希已核验，本次分析没有新增模型请求或修改原评分。

## 同一99道benchmark题的整体变化

RL完成全部100题，成绩49/100；SFT尚有一题因服务故障缺失。因此下面三阶段统一比较共同完成的99题，每题一次，使用同一问题、参考答案、主模型采样设置和GLM评分协议。

| 指标 | Base | SFT后 | RL后 |
| --- | ---: | ---: | ---: |
| 答对题数 | 53/99 | 50/99 | 49/99 |
| 正常结束并给出最终回答 | 82/99 | 97/99 | 97/99 |
| 未正常结束的题数 | 17 | 2 | 2 |
| 平均模型轮次 | 7.91 | 4.78 | 4.82 |
| 90%分位模型轮次 | 26.6 | 7.0 | 6.2 |
| 工具调用总次数 | 693 | 376 | 380 |
| 工具参数错误次数 | 39 | 11 | 15 |
| 平均步骤格式合规率 | 77.0% | 75.8% | 80.2% |
| 每题步骤格式合规比例的平均值 | 77.0% | 75.8% | 80.2% |
| 完全相同动作的额外调用次数 | 358 | 72 | 82 |
| 主模型输入tokens合计 | 14.95M | 4.95M | 5.02M |
| 主模型输出tokens合计 | 430,635 | 98,033 | 98,766 |

输入tokens按每次请求实际输入累计，包含重复发送的历史；输出包含思考。格式合规按作者正则及工具错误标记对实际全部步骤计算，再对99题平均，区别于训练时截取fatal前缀后的格式奖励。完全相同动作按工具名和完整参数JSON相同统计，不能把每次重复都直接认定为无用。耗时混有缓存、网络、暂停与恢复，故不将总墙钟时间作为训练加速证据；token减少也不等同于人民币账单同比下降。

## SFT：主要改善了Agent行为和资源消耗

SFT后，17道未正常结束的题减少到2道；其中15道恢复正常作答，这15道的正确数从1道变为5道。工具调用减少45.7%，工具参数错误减少71.8%，主模型输出tokens减少77.2%，完全相同动作的额外调用减少79.9%。模型仍会在个别题上循环，但Base中长轨迹的普遍程度明显下降，正常题的轮次中位数仍为3轮。

这项收益没有转化成总准确率提高：8道由错变对、11道由对变错，净少3道。一个直观例子是eval-0017的四图对比度题：Base选择参考答案对应的第1张，SFT选择第4张，RL仍选择第4张。能够及时给出简洁答案，并不保证视觉判断正确。

## RL：格式奖励提高，综合解题收益未体现

SFT到RL，99题中正常结束数均为97，平均轮次4.78到4.82，工具调用376到380，输出tokens98,033到98,766。这些变化很小。按同一严格正则复算的平均步骤格式合规比例从75.8%到80.2%，显示格式有所改善。工具参数错误次数11到15，仍低于Base的39次，但没有继续改善；其中裁剪越界9到12次，搜索词超过服务长度限制1到3次。错误涉及的题数为Base3道、SFT5道、RL7道，说明Base的较多错误集中在少数反复失败的题里，不能只看总次数推断所有题都更稳定。

按原自动评分，RL相对SFT有4道由错变对、5道由对变错，90道对错保持不变；净差只有1道。本轮结果不足以证明稳定退化，也没有准确率提升证据。

验证集是另留的16道训练来源题，每题4次，共64条回答。64条的答案准确性都可由已缓存裁判结果或原有无终端答案记0规则确定；缺失的是其中一条搜索质量query评分，因此完整组合奖励只有63条。

| 16题、64条回答的答案指标 | SFT | RL |
| --- | ---: | ---: |
| 答案正确数 | 38/64，59.4% | 36/64，56.3% |
| 四次全部答对的题数 | 6/16 | 6/16 |
| 四次全部答错的题数 | 4/16 | 5/16 |
| 平均格式奖励，全部64条 | 0.5408 | 0.6692 |

| 完整奖励齐全的相同63条 | SFT | RL |
| --- | ---: | ---: |
| 平均格式奖励 | 0.5493 | 0.6703 |
| 平均搜索质量奖励 | 0.5683 | 0.5444 |
| 平均组合奖励 | 0.3532 | 0.4190 |

64条答案准确率为SFT38/64、RL36/64；5条从错变对，7条从对变错，其余52条对错相同。两组各有6道题四次全对，RL四次全错从SFT的4题变为5题。

组合奖励为格式×（0.8×准确性＋0.2×搜索质量）。同63条奖励净增0.0658，按对称乘积公式拆分，格式变化贡献+0.0835、准确性变化贡献−0.0165、搜索质量变化贡献−0.0012，三项相加恰为净变化。这是公式的代数分解，不是训练因果估计；本轮组合奖励上升由格式项带来。

## 哪些题型和具体行为变了

| 同题子集 | Base | SFT | RL |
| --- | ---: | ---: | ---: |
| SimpleVQA | 17/19 | 15/19 | 15/19 |
| InfoSeek | 8/20 | 7/20 | 7/20 |
| VDR | 4/20 | 5/20 | 4/20 |
| FVQA | 7/10 | 8/10 | 9/10 |
| MMSearch | 6/10 | 3/10 | 3/10 |
| LiveVQA | 6/10 | 7/10 | 5/10 |
| BrowseComp-VL | 5/10 | 5/10 | 6/10 |

各子集只有10至20题，增减一题就会明显改变比例；FVQA的RL增益中还有一题明确受到裁判波动影响。

三个具体案例有助于理解变化：

- **eval-0101，VDR：RL修正了实体识别。** 问题要求识别马车供马组织和背景商店。Base和SFT均未正确给出供马组织，RL给出与参考答案相符的殡仪馆及打印商店名称。轨迹中出现裁剪、超分、图搜和文字检索，是一次有用的多工具完成案例；摘要后端差异使其不能单独证明RL学会了该策略。
- **eval-0184，BrowseComp-VL：RL恢复了SFT丢失的事实。** 问题问车辆上市时间、充电时间和功率。SFT的充电时间与参考答案不符，RL三项均匹配；Base原本也正确，因此这是相对SFT的恢复，并未超过Base。
- **eval-0176，LiveVQA：RL重新出现循环。** SFT最终给出正确选项A，RL进行50轮后仍停留在搜索阶段，没有给出有效答案。整体97题正常结束不代表每一道题的行为都得到保持。

## 解释结果时的边界

**裁判存在可确认的波动。** eval-0083中，SFT和RL抽取答案逐字节相同，均为2025-04-04，前者被判错、后者被判对。RL裁判理由又明确表示日期不匹配，与其开头`correct: yes`矛盾。原始评分保留，没有重新判分；4个账面RL增益中至少有这1个不能算模型回答改善。

**RL评测中摘要部署发生了变化。** Base/SFT使用PyTRIO27B，RL因服务故障使用用户自部署27B；两端权重、量化和服务实现未核实完全一致。因此跨阶段结果只能作为本次实际实验观察，不能精确分离RL权重更新与工具观察变化的影响。训练的4B模型、七工具定义、主提示词和GLM裁判保持原设置。

验证集此前已经用于观察SFT模型的任务难度，属于开发集；100题benchmark是七类公开任务的自定义子集。只运行一次且未全面人工审查评分，不能将这些成绩泛化为论文全量复现结果。RL训练为25次更新，结论仅对应这次实验范围。
