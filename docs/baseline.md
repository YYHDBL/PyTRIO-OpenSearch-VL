# 评测配置与流程检查

当前状态：`outputs/base-v1/` 已在保存 145 题后停止，其 system prompt 是自行改写的三工具版本，而 SFT 数据仍保留作者的 system prompt。该批结果保留为诊断记录，不纳入修正后协议的正式对比；提示词与工具环境需要先统一，之后使用新目录运行。

基模为 `Qwen/Qwen3.5-4B`；计划中的 SFT 使用 LoRA rank 32。正式比较 Base、SFT 和 RL 时共享固定的 200 题、提示词、工具环境、轮数限制和裁判。

## 数据分布

评测集包含 SimpleVQA 40、InfoSeek 40、VDR 40、FVQA 20、MMSearch 20、LiveVQA 20、BrowseComp-VL 20。BrowseComp-VL 的 Level 1/2 为 6/14。

各来源内部采用 seed 42 随机抽样，并未逐题型分层。VDR 当前 40 题的 base/hard1/hard2 为 9/12/19，相应的 500 题候选池为 105/152/243。MMSearch 当前 20 题覆盖其视觉候选池 13 类中的 11 类。总体准确率受 40/20 配比影响，同时报告各来源准确率和七项宏平均。

## 七题流程检查

2026-10-27，分别使用七类任务的首个固定样本进行流程检查，结果单独保存于服务器 `outputs/baseline-pilot-v1/` 和 `outputs/judge-pilot-v1/`。它们不作为正式 200 题结果。

七题都执行到终止：4 题正常回答、2 题在工具轮数耗尽后回答、1 题因连续 3 次工具错误终止。GLM-5.3-Flash 判对 3 题。模型返回的输入 token 合计 99597，输出 token 合计 2548；这些计数不是实际人民币账单。独立图片搜索预检验证了 SerpApi 图片上传与 Lens 调用。

已验证的行为包括真实裁剪、Serper 搜索、Jina 网页读取、SerpApi 图片搜索、裁判接口，以及重跑已完成七题时不增加采样请求。单元测试覆盖工具解析、思考文本隔离、图片尺寸、裁剪边界、磁盘缓存和裁判格式校验。

## 评分与边界

裁判提示词与参考版本 OpenSearch-VL 的 `opensearch_vl/eval_with_gpt4o.py` 一致。本实验使用用户提供的 GLM-5.3-Flash Anthropic Messages 接口，替代论文的 GPT-4o。空最终回答直接计错；裁判网络或格式错误会停止评分并保留进度，不静默计错。

工具环境是三工具的缩小配置。文字搜索读取前两项的网页正文，最多各保留 5000 字符，没有使用论文的专门网页摘要模型。搜索和网页内容缓存用于三个阶段重复请求的可比性；不同请求仍会受实时网络变化影响。

200 题是从 VDR 作者发布的评测子集再次抽样得到，不能直接对照原论文全量分数。FVQA 的确切数据版本关系仍待确认，见 [数据说明](data.md)。

## SFT 规模

公开常规版 36592 条 SFT 文件中，按 assistant 文本里的 `<tool_call>` 计数，平均每条 2.648 次；选中 512 条平均 2.11 次、范围 1 到 5 次。它与论文报告的 6.3 轮不能直接视为相同统计口径。512 条可作为本次预算下的冷启动规模，效果需要训练及固定评测验证。当前数据的图文长度与 loss mask 已完成 [CPU 验收](sft-audit.md)；训练与评测提示词仍需统一。

## 执行

在服务器项目目录设置可用网络后运行：

```sh
bash run_baseline.sh
```

脚本依次生成 `outputs/base-v1/` 和评分到 `outputs/judge-base-v1/`，结束时在 `logs/baseline.exit` 写入退出码。`0` 表示整段命令正常结束，是否齐全还需查看评分摘要中的 `complete`、`generated` 和 `scored`。失败时重跑相同命令会复用已完成结果和中断状态。生成配置、预算与缓存规则见 [README](../README.md)。
